The one rule that governs all animations on a conversion site

Every animation must do one of two things: guide the eye toward a CTA, or give positive feedback that reduces friction. Everything else gets deleted.

Your notes said it plainly: "If an animation doesn't guide attention toward the CTA or clarify information, remove it." This is the filter you run on every existing animation and every new one you consider adding. Animation for decoration is noise. Animation for conversion is a tool. The difference is intention.

On a dark site this matters even more — any animation on a near-black background draws enormous attention because there's so little competing for the eye. A decorative animation on #050505 will actually pull focus away from your CTA. That's the opposite of what you need.

All animation CSS — the complete system
/* ── 1. SCROLL FADE-IN (add .fade-in class to every section) ── */
.fade-in {
  opacity: 0;
  transform: translateY(20px);
  transition: opacity 350ms ease-out, transform 350ms ease-out;
}
.fade-in.visible { opacity:1; transform:translateY(0); }

/* ── 2. CTA BUTTON — primary (accent color) ── */
.btn-primary {
  transition: background 180ms ease, transform 180ms ease, box-shadow 180ms ease;
}
.btn-primary:hover {
  background: #17965f; /* darken accent */
  transform: scale(1.02);
  box-shadow: 0 4px 20px rgba(29,181,116,0.30);
}

/* ── 3. SECONDARY BUTTON ── */
.btn-secondary {
  transition: background 180ms ease, border-color 180ms ease;
}
.btn-secondary:hover {
  background: rgba(255,255,255,0.04);
  border-color: rgba(255,255,255,0.22);
}

/* ── 4. CARD HOVER LIFT ── */
.card {
  transition: background 200ms ease-out, border-color 200ms ease-out,
              transform 200ms ease-out, box-shadow 200ms ease-out;
}
.card:hover {
  background: #1a1a1a;
  border-color: rgba(255,255,255,0.12);
  transform: translateY(-2px);
  box-shadow: 0 8px 28px rgba(0,0,0,0.45);
}

/* ── 5. NAV LINK UNDERLINE SLIDE ── */
.nav-link { position:relative; transition:color 200ms ease; }
.nav-link::after {
  content:''; position:absolute;
  bottom:-2px; left:0; right:0; height:1.5px;
  background:#1DB574;
  transform:scaleX(0); transform-origin:left;
  transition:transform 200ms ease;
}
.nav-link:hover::after { transform:scaleX(1); }

/* ── 6. IMAGE ZOOM ── */
.img-wrap { overflow:hidden; border-radius:8px; }
.img-wrap img { transition:transform 400ms ease; }
.img-wrap:hover img { transform:scale(1.04); }

/* ── 7. FORM FIELD FOCUS + VALID CHECKMARK ── */
.form-input { transition:border-color 150ms ease, background 150ms ease; }

  opacity:1; transform:scale(1);
}

/* ── 8. FAQ ACCORDION ── */

  max-height:0; overflow:hidden;

}
.faq-row.open + .faq-answer { max-height:200px; }

.faq-row.open .faq-icon { transform:rotate(45deg); }

/* ── 9. ACCESSIBILITY WRAPPER (REQUIRED) ── */
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
The scroll fade-in JavaScript — wire it to every section
Intersection Observer — add .fade-in to any element you want to animate in on scroll
// Trigger fade-in when elements enter viewport
const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) {
      entry.target.classList.add('visible');
      observer.unobserve(entry.target); // fire once only
    }
  });
}, { threshold: 0.12, rootMargin: '0px 0px -40px 0px' });

// Apply to all sections and stagger child cards
document.querySelectorAll('.fade-in').forEach(el => observer.observe(el));

// Stagger children inside a section (e.g. service cards)
document.querySelectorAll('.stagger-children').forEach(parent => {
  parent.querySelectorAll(':scope > *').forEach((child, i) => {
    child.style.transitionDelay = `${i * 80}ms`;
    child.classList.add('fade-in');
    observer.observe(child);
  });
});
Where to apply each animation — section by section map

Section-by-section animation map

Section 1 (Hero): No scroll fade — it must be instantly visible. Headline, subheadline, and CTA buttons get no entrance animation. Only button hover states apply here.

Section 2 (Trust strip): Fade-in as one unit. The badges inside stagger by 80ms each left to right.

Section 3 (Authority stack): Cards stagger in with 80ms delay between each badge/credential card.

Section 4 (Photos): Fade-in the grid as one unit. Each image gets the hover zoom effect.

Section 5 (Video): Section fades in. No animation on the video player itself.

Section 6 (How It Works): The 3 steps stagger in with 100ms delay between each step.

Section 7 (Reviews): Cards stagger in. No animation inside video thumbnails.

Section 8 (Services): Service cards stagger in with 80ms delay. Urgency banner fades in last.

Section 9 (Breather): The whole section fades in as one unit — headline, then buttons 150ms later.

Section 10 (Pricing): 3 pricing cards stagger in with 100ms delay. Featured card appears slightly earlier (0ms delay, flanking cards at 100ms and 200ms).

Section 11 (FAQ): Each FAQ row fades in with 60ms stagger. Accordion open/close uses the max-height CSS animation.

Section 12 (Final CTA): Headline fades in, then buttons 150ms later. Phone number 250ms after that.

Do this / never do this
Do this
  • Wrap everything in prefers-reduced-motion
  • Keep all transitions under 400ms
  • Use ease-out for entrances (fast start, slow end)
  • Use ease-in for exits (slow start, fast end)
  • Stagger child elements by 80ms — never all at once
  • Only animate transform and opacity — never width/height
  • Use translateY(20px) for scroll fade — not translateX
  • Apply hover state on card container not inner elements
  • Fire scroll animations once — never re-trigger on scroll back
  • Test every animation on a real phone before shipping
Never do this
  • Animate width, height, top, left — causes repaints (slow)
  • Use transitions longer than 400ms anywhere
  • Loop decorative animations forever
  • Add a page intro / loading animation
  • Use slide-in from left or right on sections
  • Animate the hero section entrance (it must load instantly)
  • Use parallax scrolling — kills mobile performance
  • Add a typewriter effect on any headline
  • Use JavaScript for something CSS can do
  • Forget prefers-reduced-motion — it's not optional

The performance rule — only animate transform and opacity

This is non-negotiable. When you animate transform and opacity, the browser handles them on the GPU — they're essentially free. When you animate width, height, top, left, or margin, the browser has to recalculate the layout of the entire page on every frame — this creates jank on mobile. Every animation in this guide uses only transform and opacity. The only exception is border-color and background transitions on hover states, which are acceptable because they're triggered by user input not continuous loops.
