The problem you need to solve — why #050505 and #111111 alone aren't enough
The core issue

Two background values creates a flat, depthless page — you need a 5-level background system to create hierarchy on dark

On a light site, whitespace and contrast do the work of creating depth and hierarchy. On a dark site, you need more background levels because the contrast range is compressed. With only #050505 and #111111, everything sits on the same visual plane — cards don't feel elevated, sections don't feel distinct, and the page reads as one long dark wall. The fix isn't to add bright colors — it's to build a precise 5-step background system where each level is subtly lighter than the last, creating depth without ever looking colorful.

Your notes said "the brain reads premium through visual hierarchy." On dark sites, that hierarchy is built almost entirely through subtle background variations and precise text opacity levels — not through hue changes.

Why these exact 5 values and not others

The gap between each level is carefully calculated. #050505 → #0a0a0a is a 5-point jump — barely perceptible, just enough to suggest "this is a different zone." #0a0a0a → #111111 is a 7-point jump — visible but subtle. #111111 → #1a1a1a is a 9-point jump — clearly a different level, creates the "elevated" feeling for featured sections. The jumps get slightly larger as you go up because the human eye is less sensitive to value differences in very dark tones. Arbitrary values (like #0d0d0d or #181818) will look slightly off — these exact hex values align to clean visual steps.

Why rgba opacity instead of fixed hex values for body text

On a dark site, using rgba(255,255,255,0.55) for body text instead of a fixed hex like #8a8a8a is critical because your background isn't perfectly consistent — you have #050505, #0a0a0a, #111111, and #1a1a1a. If you use a fixed grey hex, that grey will look slightly different on each background. With rgba opacity, the text automatically adjusts its apparent brightness relative to whatever background it sits on — giving you consistent visual hierarchy across all 5 background levels without having to calculate different values for each.

The border system — why solid hex borders look wrong on dark
The most common dark-site mistake

Never use solid hex colors for borders on a dark background — use rgba opacity only

If you write border: 1px solid #333333 on your cards, it will look fine on #050505 but slightly too harsh on #111111 and #1a1a1a sections. The border appears to change weight depending on background. Instead write border: 1px solid rgba(255,255,255,0.06) — this border is always 6% white regardless of background, so it stays visually consistent across all 5 background levels automatically.

Default card border: rgba(255,255,255,0.06) · Hover border: rgba(255,255,255,0.12) · Focus border: your CTA color at full opacity · Section dividers: rgba(255,255,255,0.04)
Good palette vs bad palette — the difference on a dark site
Wrong — too many colors, random hues
Using 6 accent colors creates visual chaos. The eye doesn't know what to focus on. Every element competes equally. Nothing stands out — including the CTA. Your notes: "Random colors create a messy feeling that drives users away."
Right — one accent, everything else neutral
4 background levels + 1 accent + off-white text. The accent color (#1DB574) is the only hue on the page — so it commands 100% of the eye when it appears. Every CTA, every important link, every trust signal uses this one color. Nothing competes with it.

--text-primary: #F5F5F0;
--text-secondary: rgba(255,255,255,0.55);
--text-muted: rgba(255,255,255,0.30);

/* Borders — opacity system */
--border-default: rgba(255,255,255,0.06);
--border-hover: rgba(255,255,255,0.12);

/* CTA accent — your one brand color */
--accent: #1DB574;
--accent-dark: #17965f /* hover state */;
--accent-glow: rgba(29,181,116,0.12) /* subtle tinted bg */;
--accent-text: #04342C /* text ON the accent button */;

/* Urgency only */
--urgency: #E8A020;
Do this / never do this
Do this
  • Use the 5-level background system — never just 2 values
  • Define all colors as CSS variables — never hardcode in components
  • Use rgba opacity for all borders — never solid hex borders
  • Use rgba opacity for secondary/muted text — not fixed greys
  • Pick ONE accent color and use it only for CTAs and key links
  • Make sure your CTA passes 4.5:1 contrast ratio on all backgrounds
  • Use --accent-glow for subtle accent-tinted card backgrounds
  • Keep amber/orange for urgency banners only — not as a second accent
  • Test every text level on every background level for readability
Never do this
  • Use more than 1 accent hue as a "brand color" — it splits attention
  • Use solid hex borders like #333 — they look wrong across bg levels
  • Use pure white (#ffffff) for text — too harsh, feels cheap on dark
  • Use pure black (#000000) for the deepest background — too flat
  • Add a colored section background (red/blue/green) on a dark site
  • Use your accent color for decorative elements — reserve it for action
  • Use more than 5 background levels — creates visual noise not depth
  • Use rgba(255,255,255,0.3) for anything important — too low contrast
